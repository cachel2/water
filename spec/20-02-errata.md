# 20.2 · Errata and contradictions

An **erratum** closes a hole this document did not know it had, and only if all four hold: the document gives *no* answer (not an inconvenient one); the fix is the smallest rule consistent with everything frozen and is *derived* rather than chosen; it adds no keyword, operator, production, or concept; it is recorded here, dated, with the rule it came from. If closing a hole needs a *decision*, that is a change, forbidden by §20.1 — the hole gets the most restrictive answer available (a compile error) and the decision goes to `ideas/`.

**A contradiction is not a hole.** A hole is silence; a contradiction is the document giving two incompatible answers, and §20.2's first condition ("gives *no* answer") cannot process it — the freeze-pass on t3 already met one and the earlier text had no rule for it. The resolution is an **authority order**, fixed here, applied in this sequence until one section answers:

1. **§18, the grammar.** Its LL(1) properties are declared normative (§3.1), and every other section is downstream of what parses. When prose and grammar disagree about form, the grammar wins and the prose is corrected to it.
2. **§11 and §4, the trap list and the type rules**, for questions of runtime meaning the grammar does not settle. §11.1 declares itself complete, so a behavior it omits does not trap.
3. **§8.4, evaluation order**, for sequencing.
4. **The most restrictive reading**, if the order above still leaves two live answers — the same fallback §20.2 uses for a hole needing a decision.

A contradiction resolved this way is recorded in the errata log like an erratum, tagged *contradiction*, naming the two sections and which one won. It changes no production; it only deletes the losing reading.

The four erratum conditions above still govern true holes. This clause governs only the case where the document argued with itself.

water inherits t3's freeze discipline and its already-run C23 J.2 audit; the audit's six findings are written into this document as rules (§1.4). The first two external reads of the frozen text found defects, recorded below. None changes a production of §18 — including C-001, whose first attempted fix wrongly *added* a production and was reverted (see the note under the table).

**Note on C-001.** The first fix added a `match_stmt` production to §18 — a violation of §20.1, which forbids adding a production, committed while *resolving* an erratum. It was reverted. The correct resolution of a grammar-vs-example contradiction is for the grammar to win *as written*: the example is corrected to the grammar, never the reverse. The cheapness of that first wrong fix — the document's first erratum already growing the grammar — is precisely the failure mode that ended the two prior designs, caught here by the freeze doing its job.

**C-003 (2026-08-28).** §8.2 said a write must be to a "mutable place" and listed "a field/index/deref reachable from" a mutable binding — conflating *binding reassignability* with *pointer writability* for the third time (after E-001's `*x` and C-002's parameters). It broke §19.5: `fn putc(self: *Self, …)` writing `&self.dr` requires `&self.dr : *u32`, but if that depended on `self` being a `mut` binding it would be `*const u32` and `write_volatile` would not type. §8.2 is rewritten to separate the two questions at the root — reassignability is about the *name*, writability is about the *pointer's constness* (§4.3 rule 2, `const` non-transitive). *contradiction* — §8.2 (prose) vs §4.3 + §19.5; the non-transitive-`const` rule wins; §18 untouched. That the same conflation survived two prior fixes is why §8.2 was reformulated rather than patched a third time.

**Parked, not erratum (2026-08-28).** A `match`-arm *block* ending in `return` yields `()` (§7.1) and does not unify with sibling arms of another type, so `let n = match x { Ok(v) => v, Err(e) => { cleanup(); return Err(e); } };` does not compile; the fix is a `let mut` above a statement `match` (§19.4, §7.5 rule 5). This is a design limitation with a clear answer, not a hole — §20.2 forbids treating an inconvenient answer as silence. "Divergence analysis" (making a block-tailed-in-`return` count as divergent) is a *change* and lives in `ideas/`.
